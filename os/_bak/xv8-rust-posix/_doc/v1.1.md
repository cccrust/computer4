# v1.1 — alloc / libposix Dual Target

> 主題：讓 xv8 user space 完整支援 Rust `alloc` crate，使 `Vec`/`String` 可用，並規劃 `os/posix/tools` 不需複製即可在 xv8 上編譯執行。

**狀態**：✅ Phase 1 完成 | ✅ Phase 2 完成 | ✅ Phase 3 完成

---

## 1. 背景：Linux 的軟體堆疊 vs xv8

Linux 上 Rust `std` 並非憑空出現，層層依賴：

```
┌─────────────────────────────────────┐
│ Rust std (Vec, String, Box, etc.)  │  ← 開發者直接使用
├─────────────────────────────────────┤
│ alloc crate                         │  ← #[global_allocator]
├─────────────────────────────────────┤
│ malloc (libc)                       │  ← 需要 brk/sbrk/mmap
├─────────────────────────────────────┤
│ Linux Kernel syscalls               │  ← brk(2), mmap(2)
├─────────────────────────────────────┤
│ Linux Kernel (實體記憶體)            │
└─────────────────────────────────────┘
```

xv8 目標：模仿 Linux 提供給 `alloc` 的底層介面，讓 `Vec`/`String` 在 xv8 上自動可用。

---

## 2. xv8 現況分析

### 2.1 Memory Model（已確認的設計）

xv8 是 **static binary**（kernel + user 靜態連結為單一 ELF）。Rust 的 `#[global_allocator]` 是 crate-level，只能有一個。

| 元件 | 職責 |
|------|------|
| `kernel/src/kalloc.rs` | 宣告 `#[global_allocator]`，使用 `buddy-alloc` 管理實體記憶體頁面池 |
| `kernel/src/sysproc.rs:117` (`sys_sbrk`) | syscall 12，向 buddy-alloc 請求 n bytes，回傳指標 |
| `user/src/lib.rs` | `#![no_std]` + `extern crate alloc` |
| `user/src/args.rs` | `Args::from_stack()` 從 stack 讀取 argc/argv |

**共用方式**：user 不宣告自己的 `#[global_allocator]`，直接使用 kernel 宣告的那個。`alloc` crate 的 `GlobalAlloc::alloc()` 內部呼叫 buddy-alloc，需要時透過 `sbrk(12)` 或 `mmap(34)` syscall 向 kernel 要記憶體。

### 2.2 已解決的問題

| 問題 | 狀態 |
|------|------|
| `libposix::args()` on xv8 | ✅ 已實作（從 `Args::from_stack()` → `Vec<String>`） |
| `libposix` 支援 xv8 | ✅ 已實作（`#[cfg(target_os = "none")]` 的 `open`/`read`/`write`/`close`/`exit`/`args`/`print`/`println`） |
| `os/posix/tools` 無法直接引用 | ✅ 已解決（`xv8-rust-posix/user/Cargo.toml` 已加 `libposix` dependency） |
| `File::read_to_end()` 缺乏 | ⚠️ 工具自行用 loop 實現（`od.rs` 已用 `read()` + `extend_from_slice`） |

## 3. 實作規劃

### 運作原理

`libposix` 是**跨平臺 abstraction layer**，同一份 source code 自動適配 Mac/Linux 和 xv8：

```
os/posix/tools/src/bin/od.rs
        │
        │  cargo build        cargo build --target riscv64gc-unknown-none-elf
        ▼                      ▼
┌───────────────┐      ┌─────────────────┐
│   Mac/Linux   │      │      xv8        │
│  libposix::* │      │   libposix::*   │
│   (Unix)     │      │(target_os=none)  │
├───────────────┤      ├─────────────────┤
│ libc::open   │      │  ecall open     │
│ std::env::args│      │Args::from_stack │
│ std::process │      │  ecall exit     │
│ std::io::Read│      │  ecall read     │
└───────────────┘      └─────────────────┘
```

工具程式只寫 `use libposix::{File, args, exit}`，編譯時平臺決定用哪個實作。**同一份 source code，無需複製，適用所有平臺。**

### Phase 1：讓 `Vec<String>` 在 xv8 上運作 ✅

**目標**：`libposix::args()` 在 xv8 上回傳有意義的 `Vec<String>`。

#### Step 1.1：實作 `libposix::args()` on xv8 ✅

`libposix/io.rs` 在 `#[cfg(target_os = "none")]` 區塊：

```rust
pub fn args() -> Vec<String> {
    let args = Args::from_stack();
    args.args_as_str()  // Iterator<Item = &str>
        .map(|s| String::from(s))
        .collect()
}
```

`extern crate alloc` 已在 `user/src/lib.rs` 引入。

#### Step 1.2：加 `read_to_end` helper ⚠️

工具自行用 loop 實現（`od.rs` 已用 `read()` + `extend_from_slice`），暫不需要統一實作。

### Phase 2：`libposix` 兩路實作 ✅

**目標**：`libposix/src/io.rs` 同時支援 Mac 和 xv8，提供統一的 `File`/`Read`/`Write`/`args`/`print`/`println`/`exit` API。

#### Step 2.1：確認現有 `libposix` 結構 ✅

`libposix/io.rs` 兩路實作：
- `#[cfg(unix)]` sys module：包裝 `libc` + `std`
- `#[cfg(target_os = "none")]` sys module：包裝 `ecall` inline asm
- `File` struct：Unix 用 `libc::open`，xv8 用 `sys_open`
- `Stdin`/`Stdout`/`Stderr`：Unix 用 `std::io`，xv8 用 `sys_read`/`sys_write`
- `args()`：Unix 用 `std::env::args()`，xv8 用 `Args::from_stack()`
- `exit()`：Unix 用 `std::process::exit()`，xv8 用 `ecall a7=10`

#### Step 2.2：改造 `od.rs` ✅

`os/posix/tools/src/bin/od.rs` 已改用 `libposix`：
```rust
use libposix::{File, Read, args, exit, print, println};
```

改動點：
- `std::fs::File` → `libposix::File`
- `std::env::args()` → `libposix::args()`
- `std::process::exit(1)` → `libposix::exit(1)`
- `print!()` / `println!()` → `libposix::print()` / `libposix::println()`
- `File::open(Path::new(&files[0]))` → `File::open(&files[0])`（直接 `&str`）
- `std::io::stdin().lock().read_to_end(&mut data)` → 自己用 `read()` + `extend_from_slice` loop

Mac build 成功：`cargo build --bin od` ✅
